Starting Simple: What a Network Has to Do

Slides 3/34 – 5/34

Where We Are & Today's Core Networking Question

Slide 3/34

From the Last Session (Migration):

  • Migration moves workloads to the cloud: assess, plan, migrate, test, operate.
  • Cutover usually switches a DNS entry, load-balancer targets, or routes.
  • Large data moves over the network, and the network is often the slowest part.
Today's Question: You have moved a web server and its database to the cloud. Who can reach them, how do they reach each other, and how do you keep everyone else out? Every answer is a networking decision.

A Comparison You Already Understand: The University Campus

Slide 4/34
1. Room Number
Every room has a number, so mail and people can find it ➔ Addresses
2. Buildings
Group rooms; some open to the public while others are for staff only ➔ Subnets
3. Crossing Signs
Signs at each crossing tell you which path leads where ➔ Routes
4. Gate Security
Security at the gate decides who may enter ➔ Firewalls
5. Directory
Turns "Computer Engineering office" into a building and room number ➔ DNS
A cloud network has the same parts: addresses, subnets, routes, firewalls, and DNS.

The Four Jobs of Any Network

Slide 5/34
Job The question it answers In today's session
Address Where is each machine? IP addresses, CIDR, subnets
Route Which way should a message go to reach it? Route tables, gateways
Filter Is this message allowed at all? Firewall rules
Name What address belongs to this name? DNS

In your own building, these jobs are done by physical devices: routers, switches, firewalls. In the cloud, you mostly express each job as a setting you configure, and the provider's software carries it out. (Virtual appliances — a firewall running on a VM, for example — also exist.)

Network Basics You Need for the Cloud

Slides 6/34 – 8/34

Layers: Who Does What (OSI Numbers in the Cloud)

Slide 6/34

A message passes through layers; each layer does one job. Cloud documents and exams refer to them by number.

Layer (OSI number) Examples Where you meet it in the cloud
7 Application HTTP, HTTPS (HTTP over TLS), DNS, SSH A "layer 7" load balancer reads the host and path the user asked for (for HTTPS, after it decrypts TLS).
4 Transport TCP, UDP, port numbers A firewall rule: "allow TCP port 443".
3 Network IP addresses, routing Subnets and route tables.
2 Data link MAC addresses, switches, VLANs The virtual switch inside each host.
1 Physical Cables, fiber, signals Operated by the provider inside the cloud; still yours in the office and on hybrid links.
📌 Note on Layers 5 & 6: The OSI model also has layers 5 and 6 (session, presentation). The TCP/IP model used on the internet joins layers 5–7 into one application layer.

Addresses and Ports (Must-Memorize Default Ports Table)

Slide 7/34
🚪 An IP address identifies a network interface — usually one per machine — the room.
🛎️ A port (with TCP or UDP) identifies a service endpoint on it — the counter inside the room.
Port Protocol Used by Port Protocol Used by
22 TCP SSH (Linux remote login) 3306 TCP MySQL
3389 TCP, also UDP RDP (Windows remote desktop) 5432 TCP PostgreSQL
80 / 443 TCP; 443 also UDP HTTP / HTTPS (UDP: HTTP/3) 1433 TCP SQL Server
53 UDP and TCP DNS

Learn these defaults: most firewall rules you write name one of them. A service can be configured on another port, so check the actual configuration.

TCP and UDP

Slide 8/34
TCP

Sets up a connection first, acknowledges what arrives, and resends lost pieces. If the path fails for too long, the connection breaks with an error.

  • Reliable, in-order delivery while the connection lasts
  • Used by: the web, SSH, databases
UDP

Sends each piece with no built-in delivery or ordering check. Applications may add their own (QUIC, used by HTTP/3, does).

  • No connection setup, less overhead
  • Used by: DNS queries, video calls, games
⚠️ Why it matters in the cloud: Firewall rules name the protocol as well as the port: "TCP 443" is not the same rule as "UDP 443". Allow the wrong one and the application fails — often with nothing more than a timeout.
PART 3

IP Addresses and CIDR

Slides 9/34 – 15/34

Public and Private IPv4 Addresses (RFC 1918)

Slide 9/34

An IPv4 address is 32 bits, written as four numbers from 0 to 255: 192.168.1.20.

  • Public address — globally unique and routed on the internet. Whether anyone can actually reach it depends on routes and firewalls.
  • Private address — not routed on the internet. Many homes and companies reuse the same private ranges.
Private range (RFC 1918) From – to Addresses
10.0.0.0/8 10.0.0.0 – 10.255.255.255 16,777,216
172.16.0.0/12 172.16.0.0 – 172.31.255.255 1,048,576
192.168.0.0/16 192.168.0.0 – 192.168.255.255 65,536

In the common IPv4 cloud design, machines get private addresses, and a public address is added only where the internet must reach the machine. (IPv6 and managed services follow other patterns.)

Reading CIDR Notation

Slide 10/34

CIDR (classless inter-domain routing) writes a block of addresses as starting address / number of fixed bits.
Example 10.0.0.0/16: the first 16 bits (10.0) are fixed; the last 16 bits are free.

Visual 32-Bit Split for 10.0.0.0/16 (8 bits per octet):
10 Octet 1 (8 bits fixed)
0 Octet 2 (8 bits fixed)
0 – 255 Octet 3 (8 bits free)
0 – 255 Octet 4 (8 bits free)
The One Rule to Remember
addresses in a /n block = 2^(32 - n)

for 0 ≤ n ≤ 32. A bigger number after the slash means a smaller block. The starting address has all free bits set to zero.

Block Addresses Typical use
/16 65,536 A whole cloud network
/20 4,096 A large subnet
/24 256 A common subnet
/28 16 A very small subnet
/32 1 One single address

Worked Example: Reading a /23 Block

Slide 11/34
Question: Which addresses belong to 10.0.0.0/23? Is 10.0.2.5 one of them?
  1. Free bits: 32 - 23 = 9, so the block has 2^9 = 512 addresses.
  2. 512 addresses = two groups of 256, so the third number takes two values: 0 and 1.
  3. The block runs from 10.0.0.0 to 10.0.1.255.
  4. 10.0.2.5 has 2 in the third place, so it is NOT in the block.
💡 Rule for /23: A /23 starts on an even third number: 10.0.2.0/23 covers 10.0.2.0 – 10.0.3.255. Routes, subnets, and firewall rules are written this way; if you cannot read it, you cannot check it.

Subnets, and the Addresses You Cannot Use (Reserved Addresses)

Slide 12/34

A subnet is a smaller block cut out of the network's block. 10.0.0.0/16 can be cut into 256 subnets of /24: 10.0.0.0/24, 10.0.1.0/24, ..., 10.0.255.0/24.

🚫 Reserved Addresses in Every Subnet

The provider keeps a few addresses in each subnet for its own use — for example the network address, the router, provider DNS, and the last address.

  • In a standard IPv4 subnet, AWS and Azure reserve 5; Google Cloud reserves 4 in a primary range.
  • So a /24 gives 251 usable addresses on AWS or Azure, not 256.
  • A /28 gives only 16 - 5 = 11. Very small subnets run out quickly.

Worked Exercise: Subnetting 10.20.0.0/16 Across 2 Availability Zones

Slide 13/34
Scenario: A company receives 10.20.0.0/16 for its cloud network. It needs three kinds of subnet — web, application, database — in each of two availability zones, each a /24 (AWS IPv4 example: each subnet sits in one zone).
1. Write down the six subnets.
• Web: 10.20.0.0/24 (Zone A) & 10.20.1.0/24 (Zone B)
• App: 10.20.2.0/24 (Zone A) & 10.20.3.0/24 (Zone B)
• DB: 10.20.4.0/24 (Zone A) & 10.20.5.0/24 (Zone B)
(Other layouts are correct if the blocks do not overlap.)
2. Which subnet contains the address 10.20.3.77?
Answer: The zone-B application subnet, 10.20.3.0/24.
3. How many usable addresses does each subnet have on AWS?
Answer: 256 - 5 = 251 usable addresses.
4. How many /24 subnets are left for later?
Answer: 256 - 6 = 250 subnets left.

Plan Your Ranges Before You Need Them

Slide 14/34

Joining two networks directly (routing or peering) normally requires that their address blocks do not overlap.

❌ Bad Plan (Overlapping)

  • Office network: 10.0.0.0/16
  • Cloud network: 10.0.0.0/16 (the default in a tutorial)
  • Address 10.0.1.5 now exists in both places. Nobody can say which one a message is for.

✅ Good Plan (Non-Overlapping)

  • Office network: 10.0.0.0/16
  • Cloud network: 10.20.0.0/16
  • Test network: 10.30.0.0/16
  • No two blocks share an address, so any two can be joined directly.

Fixing an overlap later is slow and risky: adding new ranges and migrating machines, or translating addresses (next topic). Choosing ranges that avoid it costs nothing today.

IPv4 is Running Out — and Now It Costs Money

Slide 15/34
  • IPv4 has 2^32 ≈ 4.3 billion addresses. Almost all have been handed out; addresses are now bought and sold like property.
  • Since February 1, 2024, AWS charges $0.005 per hour for each public IPv4 address, in use or idle (a few exceptions; see the price page): about $3.65 a month, or $43.80 a year, per address.
  • IPv6 uses 128-bit addresses (2^128, about 3.4 × 10^38), written in hexadecimal: 2001:db8::1.
💡 What this means for design: Give a public address only to what the internet must reach, usually just the load balancer. Everything else stays private: less exposed, and fewer address charges — though what replaces them (a NAT gateway, for example) is charged too, so compare the totals.

Virtual Networks in the Cloud

Slides 16/34 – 22/34

Your Own Private Network in the Cloud (VPC Scope by Provider)

Slide 16/34

A virtual private cloud (VPC) or virtual network is a private network inside the provider, logically separated from other customers' networks.

  • You choose its address ranges, for example 10.20.0.0/16.
  • You cut them into subnets.
  • Traffic from the internet needs a path you create and rules that allow it (check each provider's defaults).
AWS
🌐 Network (VPC): Belongs to one region
📦 Subnet: Sits in one availability zone
Azure
🌐 Network (VNet): Belongs to one region
📦 Subnet: Covers all its zones
Google Cloud
🌍 Network (VPC): Global
📦 Subnet: Belongs to one region and has its own address range

Route Tables: Which Way to Go (AWS Example)

Slide 18/34

In AWS, every subnet is associated with a route table: a list of destination ➔ where to send it.

Destination Target
10.20.0.0/16 local (stay inside the network)
0.0.0.0/0 internet gateway
  • 0.0.0.0/0 means "every address" — the default route.
  • If more than one line matches, the most specific one wins (the largest number after the slash).
  • A message to 10.20.4.9 matches both lines; /16 is more specific than /0, so it stays local.
  • The reply is routed too: every path needs a route back.

Public and Private Subnets (AWS, IPv4)

Slide 19/34

🌐 Public subnet

Its route table sends 0.0.0.0/0 to the internet gateway — the network's door to the internet.

  • For what users must reach: load balancers, web front ends.

🔒 Private subnet

No route to the internet gateway, so the internet cannot open a connection directly to a machine inside it.

  • For everything else: application servers, databases.
  • A public load balancer can still forward user requests to private machines — that is the usual design.
🔑 Three Network Conditions for Reaching a Machine in a Public Subnet

1. A public address + 2. A route to the internet gateway + 3. Firewall rules that allow the traffic.
These are necessary, not sufficient: the program must be listening, and the host firewall and the application must accept the request.

Going Out Without Letting Anyone In: NAT Gateway

Slide 20/34

Machines in a private subnet still need the internet sometimes — for software updates, for example.

Private Subnet Machine
Route: 0.0.0.0/0 ➔ NAT
Outbound request ───►
◄─── Matching reply
NAT Gateway
(Placed in Public Subnet on AWS)
Uses NAT Public IP ───►
✖ Blocks inbound start
The Internet
Update servers, etc.
  • NAT gateway (network address translation): in AWS it is placed in a public subnet, and private machines send their outgoing traffic through it (0.0.0.0/0 ➔ NAT gateway).
  • The outside world sees only the NAT gateway's public address.
  • Replies to connections the private machine started are translated back and delivered.
  • A connection started from the internet finds no matching translation, so it cannot reach the private machine.

Provider differences & cost: Azure attaches its NAT Gateway to subnets; Google's Cloud NAT is configured on a Cloud Router. Managed NAT is usually charged by the hour and per gigabyte. Alternatives: private endpoints to provider services (next topic).

Worked Exercise: Public or Private Subnet, and Public Address?

Slide 22/34
1. The internet-facing load balancer for the university's course registration website.
Suggested Answer: Public subnet, with a public address (users must reach it).
2. The PostgreSQL database behind it.
Suggested Answer: Private subnet, no public address.
3. An application server that downloads security updates every night.
Suggested Answer: Private subnet, no public address, with a route to a NAT gateway for the updates.
4. A machine that reads files from cloud storage every hour and writes reports.
Suggested Answer: Private subnet, no public address, reaching storage through a private endpoint (next topic) or through NAT.
🔑 Golden Rule: Public only when the internet must start the conversation.
PART 5

Filtering Traffic

Slides 23/34 – 25/34

Two Levels of Filtering: Stateful vs. Stateless

Slide 23/34
Machine-level firewall (AWS: security group)

Attached to the network interfaces of machines and other resources. Lists only what is allowed; everything else is denied.

• Stateful: if a request was allowed in, its reply is allowed out automatically.
Subnet-level firewall (AWS: network ACL)

Attached to a subnet. Rules can allow or deny, checked in number order.

• Stateless: every message is checked on its own, so replies need their own rule.
🔄 Stateless in Practice (Ephemeral Reply Ports):
Browser (Temporary Port 53000)
Request ➔ Dest Port 443
Dest Port 53000 ◄ Reply
Web Server (Port 443)

A browser connects from its temporary port — say 53000 — to your web server on port 443. Every reply goes back to port 53000. A stateless filter must allow that temporary range (AWS suggests 1024–65535) outward, or the connection never completes.

Example Rules for the Three-Tier Network (AWS Security Groups)

Slide 24/34
Firewall of Allow in From
Load balancer TCP 443 0.0.0.0/0 (everyone)
Application servers TCP 8080 the load balancer's firewall group only
Database TCP 5432 the application servers' firewall group only
Linux app servers, if SSH is needed TCP 22 the administrators' VPN range or a bastion host only — better, a managed session service and no open port
  • Rules can name another firewall group as the source instead of addresses. When machines are added or replaced, the rule stays correct.
  • Open only what is needed, only to those who need it: the principle of least privilege.

Common Firewall Mistakes

Slide 25/34
Mistake What happens
SSH (22) or RDP (3389) open to 0.0.0.0/0 Automated scanners find it quickly and start guessing passwords.
Database port open to the internet Anyone can try logins and known flaws directly, bypassing the application's own checks.
Reply ports forgotten in a stateless filter Connections never complete; it looks like a dead or very slow network.
Rules added "for testing" and never removed After a year, nobody knows why a door is open, so nobody dares close it.
PART 6

Network Services: Addresses, Names, Load Balancing

Slides 26/34 – 28/34

How Machines Get Their Addresses (DHCP & Static Public IPs)

Slide 26/34
  • DHCP (dynamic host configuration protocol) hands out addresses automatically. In the cloud, the provider runs it for you: each new machine gets a private address from its subnet.
  • A machine's private address normally stays with it until the machine or its network interface is deleted (details vary by provider).
  • An automatically assigned public address usually changes when the machine is stopped and started again.
  • If the public address must never change, reserve a static public address (AWS: Elastic IP) — and pay for it, as we saw.
✅ Practical rule: For service endpoints in programs and configuration, prefer a stable name to an address. The migration topic's list of problems had hard-coded addresses as a cause.

DNS in the Cloud (Zones & Record Types)

Slide 27/34

DNS turns a name into an address, and the TTL (time to live) sets how long the answer is cached. In the cloud there are two kinds of DNS zone:

  • Public zone — names the whole internet can look up, such as www.example.com.
  • Private zone — names resolvable only from networks you link to it, such as db.internal.example.com. An office can use them too, if you set up DNS forwarding (next topic).
Record Points a name to Example
A an IPv4 address db.internal.example.com ➔ 10.20.4.15
AAAA an IPv6 address www ➔ 2001:db8::1
CNAME another name shop ➔ lb-123.provider.net

⚠️ Resolving a name grants nothing: routes, firewall rules, and the service's own login still decide access.

Load Balancers (Layer 4 vs. Layer 7)

Slide 28/34

A load balancer is one service endpoint — a name, possibly with several addresses — in front of many machines. It spreads requests among them and stops sending to any machine that fails its health check (a small test request sent every few seconds).

Feature Layer 4 (network) load balancer Layer 7 (application) load balancer
Looks at Addresses and ports only The web request: host, path, headers (for HTTPS, after decrypting TLS)
Can decide "Send this connection to a healthy machine" "Send /api to these machines and /images to those"
Good for High speed; TCP and (on many products) UDP services Websites and web APIs

Across two zones, with healthy machines and enough spare capacity in each, a load balancer lets a system keep serving when one zone fails. An internet-facing load balancer is often the only part with a public address; internal load balancers have none.

PART 7

Under the Hood, and Why Distance Matters

Slides 29/34 – 30/34

How One Provider Builds Millions of Separate Networks (VLAN vs. VXLAN & SDN)

Slide 29/34
1. Traditional VLAN

A VLAN ID is 12 bits: 2^12 = 4096 values, of which 4094 can be used on one switched network. Far too few for a cloud provider hosting millions of customer networks.

2. Overlay Network (VXLAN)

Each customer's traffic is wrapped inside ordinary traffic between hosts, tagged with the customer's network number. VXLAN has a 24-bit number: 2^24 ≈ 16.7 million networks.

3. SDN (Control vs Data Plane)

Software-defined networking: decisions (routes, firewall rules) are computed by central software — the control plane; the hosts carry them out — the data plane.

This is why clicking "create network" takes seconds: no cable or switch is touched, only software settings change.

Distance Still Matters (Speed of Light in Optical Fiber)

Slide 30/34

Light in optical fiber travels about 200,000 km per second. An idealized straight fiber path gives a round-trip time that real networks cannot beat:

round trip = 2 × distance ÷ 200,000 km/s Example (Istanbul to Frankfurt): 2 × 1870 ÷ 200,000 = 0.0187 s ≈ 19 ms
From Istanbul to Straight-line distance Idealized round trip Visual Latency Scale
Ankara about 350 km about 3.5 ms
Frankfurt about 1,870 km about 19 ms
Northern Virginia about 8,420 km about 84 ms
Tokyo about 8,950 km about 90 ms

Real times are higher, often by half or more: cables do not follow straight lines, and every router on the way adds delay.

✅ Choose a region near your users, and keep parts that talk to each other a lot — an application and its database — in the same region.

8-Point Lecture Summary

Slide 32/34
  1. A network has four jobs: address, route, filter, name. In the cloud each one is a setting.
  2. A /n IPv4 block holds 2^(32-n) addresses; in a standard subnet AWS and Azure reserve 5, Google Cloud 4.
  3. Choose address ranges that do not overlap, so networks can be joined directly later.
  4. (AWS) Public subnets route to the internet gateway; everything else stays private and reaches out through NAT or service endpoints.
  5. First network check: public address + route + firewall rule — then the program itself.
  6. Stateful filters remember replies; stateless filters do not.
  7. Prefer names to addresses for services; a load balancer across two zones helps only with enough capacity in each.
  8. Distance adds delay no provider can remove.
